# Dataviz Extract

Use `dataviz-extract` during a chart repair, in parallel with `dataviz-brief`, to read the underlying data out of the source image. The rebuild is designed forward from this table plus the brief - not traced from the picture - so the table has to be complete enough to build any chosen form on.

## Why it exists

If the repair is going to change the form (a stack becomes small multiples, say), it needs every cell of the data, not just the totals or the envelope. Colour is data, not decoration: a chart that stacks ten models by week carries ten numbers per week, and the new form needs all of them. Reading the totals off the source is not enough.

It is a vision task, but a value read is not one "look and say a number" guess - a guessed absolute magnitude is the read models are worst at, worse still on a log axis, and a lone glyph read of a printed label is no safer (a `6%` transcribed as `0%`, a shifted decimal, a dropped thousands separator, a `3` read as an `8` all pass unchallenged when nothing grounds the number). So every cell is read the same way - one path, not two - grounding the value in the mark's position whether or not a label is printed. The position is **always** read: name the two nearest printed ticks that bracket the mark and the fraction between them, coarse enough to say which band the mark sits in. That bracket read is one models do reliably, stays local so scale error does not accumulate, and needs no special reasoning for a log axis. If a label is printed it is transcribed too, glyph by glyph, and read *together with* the position in the same pass, then the value is picked once inline: if the label falls inside (or one neighbour past) the mark's band the label is used - the position confirmed it, the label carries the exact digits; if the label lands nowhere near the band it is a gross misread and the position is trusted instead. This is one shot, not a loop - hold both numbers, pick, emit; no flag, no re-read stage, occasionally wrong is acceptable. When no label is printed the position is the value. The position arithmetic runs through the `read_marks_from_anchors` MCP tool - now the normal path for every cell, labelled or not - which does the scale math while the perception stays with the reader; only if the server is genuinely absent is the same bracket interpolated by hand, never by eyeballing an absolute value.

## What it produces

- The **category members**, listed by name.
- The **periods** or x-positions, listed - together with the axis anchors exactly as printed: every legible tick label (a year, a category, a value gridline), its position, and the axis's stated meaning and unit. Those labels are read directly off the image, so they are preserved exactly and kept separate from any finer per-observation position that is only inferred. Uncertainty about where a single observation sits inside a labelled interval - which month within a printed year, which day within a printed week - never licenses discarding the coarser labels the axis actually prints; the printed labels carry through and the finer uncertainty is recorded on its own. Synthetic sequential ids (P01, P02 ...) stand in for positions only when the axis prints no labels at all, never as a replacement for labels that could be read. A period is a position the source plots values at: one named only in a title, legend or note, with no marks drawn for it, is context for the caption - never a row, a gap, or an axis tick.
- A value for **every (plotted period × category) cell** - no gaps. Cells that cannot be read cleanly are estimated and marked approximate, but they still exist.
- **Units and any transformation** visible on the source (counts, %, index, log axis, share-of-total, cumulative), so the rebuild does not silently change the measure.

## Precision and honesty

Exact values are used when the prompt supplies them or when they are printed as labels. Reading values off an image is inherently approximate - that is self-evident and does not need announcing on the chart or repeating through the brief, so the skill neither hedges every number nor stamps "approximate" as chart furniture. The real rule is the anti-fabrication one: no digits the image cannot support, no rounding toward rounder-sounding numbers. Difficulty of reading a value is never a reason to drop the category it belongs to; deciding a category is not key is the brief's job, made in message terms. The same guard covers axis labels: a printed label is directly-read data, so difficulty placing individual observations is never a reason to swap readable labels for synthetic indices - that erases what the source actually gave.

Values and labels part company on one point. A value may be estimated: it is a reading within a known scale, so filling a cell approximately is honest. A label - a category name, a series name, an axis tick - is read-only text: you read it off the image, or you carry it as an explicit placeholder tied to its position (`series 4`, `[unreadable]`, `[partial: "GP…"]`). What you never do is manufacture a plausible-sounding name from the headline, a neighbouring label, or what the thing "should" be called - nor normalise a name you did read toward a more familiar one the prior expects. Snapping an unfamiliar label to the nearest well-known name is the same fabrication as gap-filling, just driven by the prior; a label that reads as novel is data as-read, and when the letters don't resolve it becomes a placeholder, not the recognised name closest to it. A confident wrong name is worse than a blank one, because it looks real and every downstream check waves it through - the chart comes out clean and says something false. The pull to keep every category and fill every cell is about count and values; it is not a licence to invent identity.

One row is one observation - one mark. A number printed beside a mark but not drawn by it (a growth rate on a revenue bar) is its own column on that mark's row, never a row of its own, or it lands on the value scale as if it were revenue. A mark drawn between two numbers carries both ends as columns. A visible mark is read from its geometry; a cell with nothing to read stays empty rather than being computed from its neighbours.
